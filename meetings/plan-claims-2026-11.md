# 클레임 탭 — 기획안 (board 쪽, 2026-11-09)

> 상태: **기획만**(Jin 2026-11-09 「먼저 기획만 해보고 착수는 전부 확정된 뒤에」). 코드 0.
> ⚠️ **ERP 레포에 같은 주제의 선행 기획이 있다** — car-erp `docs/design/claim-management.md`(2026-08-04, Jin 결정 포함).
> 그쪽 = 클레임 **기록·정산 차감**(재무·관리가 `vehicle_claims` 에 기입 → 다음 월정산 조정으로 담당자 부담 차감).
> 이 문서 = 그 **앞단**(영업 접수 → 담당자 검토·보고서 → 대표 승인 → 결과를 ERP 로). 두 문서는 한 흐름이어야 한다(§7 Q1).

## 1. Jin 이 말한 것(2026-11-09 원문 요지)

- 사이드바 「클레임」 탭. **지정된 사람만** 본다(기능설정에서 지정 — 선택적).
- 역할: 영업이 바이어에게 들은 문제를 적어 클레임 탭으로 넘기면, 담당자가 보고서를 쓰고 WhatsApp 으로 바이어와 해결.
- 목록 2줄: `차량번호 / 차대번호 / 바이어 / 금액 / 총 구매차량수` ↵ `클레임내용(길면 호버 전체) / ETA+14 경과`.
- ETA+14 = ETA 뒤 14일이 지나면 우리 귀책 가능성이 낮다 → **14일 지나면 처리할지 말지 사유를 적고 진행**하는 기간 지표.
- 영업 접수 때 **바이어가 보낸 Invoice·영상 업로드**(WhatsApp 인코딩이라 크기 문제 적음).
- 담당자는 드로어에서 상세를 보고 처리 → **Jin 이 주는 PDF** 에 우리가 채울 내용을 채움 → 대표에게 「이렇게 처리할 예정」을 **ERP 사내월정산처럼 승인/반려 링크**로.
- 링크 안: 우리 검차(inspected) 사진·영상 + 바이어가 보낸 사진·영상(영업 업로드분) + 담당자 PDF → 대표가 비교해 승인/반려 → board 에 반영.

## 3. 제안 흐름(초안)

```
[영업] /portal 판매내역(또는 출고완료) 행 → [클레임 접수] 드로어
       내용(자유 텍스트) + 바이어가 보낸 Invoice(pdf/jpg) + 사진·영상 업로드 → 저장
            │ ERP 차량 메타(차량번호·VIN·바이어·금액·ETA·구매대수) 스냅샷 + erp vehicle_id 키
            ▼
[담당자] /claims 탭 — 2줄 목록 → 드로어: ERP 메타 · 영업 메모 · 바이어 증빙 · 우리 검차 미디어(ssancar CDN + board 사진)
       · ETA+14 경과 칩 → 경과면 「처리 사유」 필수 → 보고서 칸(PDF 채울 값) 작성 → [대표 승인 요청]
            ▼
[대표] 서명 링크(로그인 없음, 만료) 또는 로그인 화면: 검차 미디어 ↔ 바이어 증빙 나란히 + 보고서(PDF) → [승인] / [반려(사유)]
            ▼
[board] 상태 반영 + 담당자·영업에게 종/웹푸시 → (승인 시) **ERP 로 결과 전송** → ERP `vehicle_claims` 기록·정산 차감(ERP 기획 §3)
```

상태 초안: `received`(접수) → `reviewing`(검토) → `pending_ceo`(승인 요청) → `approved` / `rejected`(사유) → `closed`(바이어와 합의 종결). 모든 전이·업로드·링크 발급·대표 결정 = `board_audit_logs` 행(기본 포함).

## 4. 화면 초안

- **목록**(Jin 2줄 그대로): 1줄 `차량번호 · 차대번호 · 바이어 · 금액(판매통화) · 총 구매 N대` / 2줄 `클레임내용(한 줄 말줄임, 호버 전체) · ETA+14 칩`(「ETA D+21 · 14일 초과」 빨강 / 「ETA D+6」 회색 / ETA 없음 「—」) + 상태 칩. 모바일은 카드 2줄.
- **접수 드로어**(영업, 포털 행에서): 내용 · 파일(여러 장, 영상 포함) · 저장. 접수 뒤 영업은 **본인 접수 건의 상태만** 본다(클레임 탭 접근 없음).
- **처리 드로어**(담당자): 위 3 의 상세 + 보고서 칸 + 「14일 초과 처리 사유」 + [대표 승인 요청] + 결과 표시 + [종결].
- **대표 화면**: 미디어 비교 2열(우리 검차 / 바이어 증빙) · 보고서(PDF 미리보기 또는 채운 값 표) · 승인 / 반려(사유 필수) · 결정 후 재진입 시 결과만.

## 5. ETA+14 규칙(초안)

- `days_after_eta = today − eta_date`(ERP 값, board 계산 0 저장). `eta_date` 없으면 칩 「—」, 사유 강제 없음(ETA 가 없는 차 = 아직 선적 전 클레임? 드묾).
- 14일 초과 **접수 자체는 막지 않는다**(영업은 받은 대로 올린다). **담당자가 대표 승인 요청을 누를 때** 초과면 「처리 사유」 필수.
- ⚠️ ERP `arrived` 는 **ETA 경과이지 입항 확인이 아니다**(§14-4) — 「실제 도착 +14」가 필요하면 ERP 가 도착일을 받아야 한다(현재 없음).

## 7. Jin 결정이 필요한 것(번호 = 회신용)

1. **ERP 기획과의 관계** — car-erp `claim-management.md` 를 **같은 한 흐름**으로 보고 board 가 앞단, ERP 가 기록·차감 뒷단으로 가는 게 맞나? 맞으면 ERP Phase 1 의 「재무·관리 수기 기입」은 board 전송 수신으로 바뀐다. car-erp 세션에 지금 알릴지, Jin 확정 뒤 알릴지.
2. **「기능설정에서 지정」의 위치** — (a) board 기능설정(super)에 「클레임 담당자」 사용자 선택 칸 신설(추천 — 같은 박스·ERP 변경 0) / (b) ERP 기능설정에서 지정하고 board 가 API 로 읽음. 또 **super·업무관리자는 지정 없이도 보나?**(다른 탭은 전부 `hasFullAccess` 통과 — 지정자만이면 첫 예외).
3. **영업 접수 진입점** — `/portal` 판매내역(또는 재고 출고완료) 행의 [클레임 접수] 버튼으로 가도 되나(ERP 메타를 그 자리에서 스냅샷 — 다시 적는 칸 0). 키 = ERP `vehicle_id`(board 를 안 거친 차도 클레임이 온다).
4. **대표에게 가는 길** = §6 (가)/(나)/(다). 반려엔 **사유 필수**로 두나(ERP 클레임 상태에 「기각」이 있고 실물에 기각 사례가 있다).
5. **PDF** — 파일을 주면 ① 채울 칸이 있는 양식(AcroForm)인지 ② 레이아웃을 재현해야 하는지 ③ ERP 기획의 CLAIM REPORT docx(바이어 통계·차량·FOB·PROFIT 4.5%·검수 유무·사유·증빙 VERIFIED·청구→환급률→확정액·결과·보상방식·결재 3단)와 같은 것인지. board 엔 PDF 라이브러리가 없다(xlsx 만).
6. **보고서에 들어갈 값 중 ERP 가 줘야 하는 것** — 바이어 **1년 구매대수·1년 클레임 건수**(by-buyer 는 총 대수만) · 차량 FOB·마진(PROFIT) — ERP 가 실어 주지 않으면 「—」. 마진은 2026-10-14 「마진율만 노출」 결정과 충돌하니 **대표 화면에만** 보이게 할지.
7. **승인 결과 → ERP** — 확정 보상액·통화·보상방식(다음 선적 미수 차감 / 해외 송금 / 적립금 — ERP 기획 §6 미결)·증빙 확인 여부를 ERP 로 보내 `vehicle_claims` 를 만들게 할지(HMAC 내부 POST, purchase-sync 틀). 아니면 Phase 1 은 board 기록만.
8. **WhatsApp** — 담당자가 수동으로 대화(기획 원문). respond.io(연동 A) 로 대화 로그를 끌어올 필요는 없다고 보면 되나.
9. **클레임 종결** — 대표 승인 뒤 바이어와 합의가 끝나면 담당자가 [종결]. 합의 금액이 승인액과 달라지면 **재승인**인가, 메모만인가.
10. **영상 크기** — WhatsApp 영상(대개 ≤16MB)은 heymanboard 한도(100M) 안. ssancarboard 박스 실효 한도는 **배포 전 확인**(런북 §8 절차, 운영 읽기).
