# 씬 워크스루(스윔레인 흐름도) — 사용법 문서 표준 기획 (2026-11-12 Jin 착수)

> 상태 = **기획 초안 · 게시 방식(Notion vs 티스토리) Jin 결정 대기**. 첫 샘플 = `mockups/transport-flow-2026-11-12.html`(탁송 배차, 로컬 루프 테스트 실측).
> Jin 목표: 「board·ERP 전 기능을 이 형태의 사용 씬으로 — 누가 봐도 쓸 수 있는 사용법」.

## 1. 무엇인가
- **씬 워크스루** = 기능 1개의 실제 씬을 처음부터 끝까지 **루프 테스트**로 돌린 뒤, 결과를 **스윔레인 흐름도** 한 장으로 남긴 문서.
  - 왼쪽 레인 = 누가/어디서(영업·알림톡·외부(업체/바이어)·ERP·관리). 오른쪽 카드 = 그 단계에서 **실제로 보이는 것**.
  - 카드 안: ① 실제 화면 캡처(헤드리스 스크린샷) ② 오가는 알림톡 본문(승인본 그대로 + 실제 값, 로컬 미발송이면 「운영에선 이렇게 간다」 표기) ③ API 요청/응답 실측값 ④ 감사 행 ⑤ 「운영 전 체크」.
- 두 가지 일을 한 번에 한다: **사용법**(직원용) + **배포 전 씬 검증 기록**(개발용). 루프 테스트가 통과한 씬만 문서가 된다.

## 2. 만드는 법 (board 기준 — 탁송 샘플이 쓴 도구 그대로)
1. 루프 스크립트(PHP, 서비스 직접 호출 → JSON) — 예: 스크래치 `loop/loop.php`(세션 임시). 운영 데이터 아님, 로컬 ERP(8001) 연동.
2. 스크린샷 — puppeteer-core(헤드리스 Chrome) 로 화면·드로어·공개 페이지·종 캡처 → `mockups/<기능>/*.png`.
3. HTML — 레인·카드·카톡 말풍선·코드 블록 네 가지 스타일만(`mockups/transport-flow-2026-11-12.html` 복제). 본문 14px.
4. 숫자·시각은 실측값 그대로 두되, 「업무 가이드」용으로 게시할 땐 예시값으로 바꾼다.
- 🚫 알림톡 본문은 반드시 코드 `AlimtalkTemplates` 의 `render()` 로 만든다(손으로 옮겨 적지 않는다 — 승인본과 어긋남 방지).
- **🚫 사용자용 문장에 개발 용어 금지(Jin 2026-11-12)** — 직원이 읽는 문서다. 변수명·컬럼명·엔드포인트·상태 코드(`purchase_unpaid`, `POST /requests`, 201, `transport_request_sent`)를 본문에 쓰지 않는다. **「어느 화면에서 무엇을 누르면 무엇이 보인다」**로만 쓴다(예: 「드로어 「탁송 배차」 탭에서 [배차 요청 보내기]를 누르면 이력에 「배차 요청중」이 뜹니다」). 금액·번호는 예시값.
  - 개발 상세(요청/응답·감사 행·코드 경로)는 카드 맨 아래 **접힌 「개발 상세」 블록**(`<details>`)에만 둔다 — 같은 문서 한 장으로 직원·개발 둘 다 쓰되 기본으로는 안 보이게.
  - 첫 샘플(`transport-flow-2026-11-12.html`)은 개발자용 초판이라 본문에 개발 용어가 있다 — 게시 전 사용자용으로 고쳐 쓴다(§6-3 전에).

## 3. 게시 방식 — Notion 만 vs 티스토리 + Notion 링크 (Jin 결정)
| | A. Notion 업무가이드 안에 카드로 | B. 티스토리 블로그에 HTML 게시 + Notion 에 링크 |
|---|---|---|
| 화면 캡처 | ✗ 지금 발행 도구(`cards.json`)는 글만. 이미지는 외부 URL 호스팅 + 발행 스크립트 image 블록 지원 추가 필요 | ✓ 티스토리 글에 이미지 업로드·HTML 그대로(스타일 포함) |
| 레이아웃(레인·말풍선) | △ 콜아웃·코드 블록으로 근사 | ✓ HTML 그대로 |
| 챗봇 색인(RAG) | ✓ 카드가 곧 색인 → 챗봇이 답한다 | ✗ 티스토리는 색인 안 됨 → **요약 카드는 Notion 에도 두고 「자세히 = 링크」** |
| 접근 제어 | ✓ 사내 Notion | △ 티스토리는 공개(비공개/보호글 가능하나 링크 공유는 열림) — **내부 화면·번호·금액이 들어간 문서라 공개 게시 금지**, 보호글(비밀번호) 또는 비공개+초대로 |
| 자동 포스팅 | Codex 전달 패킷(기존 절차) | Jin 집 PC `php-start` 세션이 티스토리 자동 포스팅 경험 있음 → 그 방식 재사용(Remote Control 로 문의 예정) |
| 유지보수 | cards.json 한 곳 | HTML 파일(레포 `mockups/`) + 글 ID 매핑 한 줄 |

**board 제안** = **B + A 요약**: HTML 원본은 레포 `mockups/` 에 두고 티스토리(보호글)에 그대로 게시 → Notion 기능 카드에는 **요약 카드(단계별 1~2줄) + 「흐름도 보기」 링크**. 챗봇은 요약으로 답하고 사람은 링크로 그림을 본다. 이미지 호스팅 문제·Notion 레이아웃 한계를 한 번에 피한다.
- 보안 조건: 티스토리 글은 **보호글(비밀번호)** 고정, 스크린샷에 실명·전화·계좌·실금액이 안 보이게(샘플은 테스트 계정·마스킹 번호·가짜 금액이라 OK — 운영 캡처 금지).
- 미정(Jin): 티스토리 계정·카테고리, 보호글 비밀번호 운영, 자동 포스팅 방식(php-start 세션 확인 뒤).

## 5. Notion 카드 변환 규칙 (샘플 = 탁송, `cards.json` 그룹 B 끝에 추가)
- 카드 1장 = 단계 1개(제목 「씬 · 탁송 배차 ① …」). rows = `누가`·`무엇`·`화면`·`알림톡`·`ERP`·`확인`·`흐름도` 중 해당 것만. 알림톡 본문은 줄바꿈 대신 「 / 」로 이어 붙인다(카드 행은 한 문단).
- 새 그룹을 만들지 않는다(`--replace` 회피) — 기존 그룹 끝에 `--card … --apply` 로 추가. 챗봇 질문 예시 행을 첫 줄에.
- 흐름도 링크 행은 게시 방식 결정 뒤 URL 을 넣는다(그 전엔 「레포 mockups/transport-flow-2026-11-12.html」).
