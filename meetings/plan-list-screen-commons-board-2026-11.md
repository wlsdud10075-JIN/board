## 1. ① 검색공용

**지금(실측)**

| 화면 | 방식 | 프로퍼티 | 대상·정규화 | 근거 |
|---|---|---|---|---|
| 매입예정 | 버튼·Enter, 입력↔적용 분리 | `qInput`→`q`, `vinInput`→`qVin`(`#[Url]`) | 차량번호(공백 무시)·바이어 2칸·담당자(관계) / 차대번호 · LIKE 이스케이프 | listings/index:61-112 |
| 사용자 관리 | 버튼·Enter, 분리 | `search`→`appliedSearch`(Url 없음) | 이름·이메일·전화(하이픈 무시) · 이스케이프 | users/index:36-108 |
| 알림톡 로그 | 버튼·Enter, 분리 | `search`→`appliedSearch` | 전화·템플릿·지역·사용자명(관계) · 이스케이프 | admin/alimtalk-logs:21-72 |
| 감사 로그 | 버튼·Enter, **분리 없음**(한 화면에 검색 2개) | `search`(q), `eventSearch`(eq) | 차량번호·사용자·옛값/새값 / 차량번호·이벤트·오류 · 이스케이프 없음 | audit/index:28-187 |
| 관리자 | **치는 동안 조회**(400ms) | `search`(Url 없음) | 차량번호·매물번호·소유자 · 정규화 없음 | manage/index:112-115, 347 |
| 클레임 | **치는 동안 조회**(400ms) | `q`(`#[Url]`) | 차량번호(공백 무시)·VIN·바이어 · 이스케이프 없음 | claims/index:29-73, 329 |
| 포털 판매내역·재고 | **치는 동안 조회**(300/400/600ms) | `buyerSearch`·`vehicleSearch`·`invSearch` | 판매내역 = 받아 온 행을 화면에서 거름 / 재고 = ERP 파라미터 | portal/index:2211-2234, 2483 |

**board 에 맞추면**
- 트레이트 `ListSearch`(입력 프로퍼티 + 적용 프로퍼티 + `searchNow()`) + `<x-…search-bar>`. board 는 **입력↔적용 분리**를 표준으로 둔다 — board 화면에는 live 필터(select·날짜)가 같이 있어, 분리하지 않으면 다른 필터를 건드릴 때 치던 검색어가 같이 적용된다(감사 로그가 지금 그 상태).
- `searchColumns()` 선언에 **정규화 표시**가 필요하다(ERP 정본엔 없음): 차량번호 = 공백 무시, 전화 = 하이픈 무시. 예 `['vehicle_number:plate', 'phone:digits', 'creator.name']`. LIKE 이스케이프는 공용이 항상 한다.
- 선언으로 안 되는 화면 = 훅 오버라이드: 매입예정(칸 2개), 감사 로그(한 화면에 목록 2개 — 트레이트 한 벌로는 안 됨. 두 번째 검색은 화면에 남기거나 이름 붙인 인스턴스를 지원).
- 포털은 **대상에서 뺀다** — DB 쿼리가 아니라 ERP 응답을 다루는 화면이다. 단 재고 검색(`invSearch`)은 치는 동안 ERP 를 부르므로(분당 120 공유 한도) 버튼식으로 바꾸는 것만 따로 볼 만하다.

**Jin 결정 ①** 관리자·클레임(·포털 재고) 검색을 「버튼·Enter 로만」으로 바꾼다 = **화면 동작이 달라진다**(지금은 치면 바로 걸러짐). ERP 규칙과 맞추려면 바꿔야 하고, 「기존 화면은 동작 무변경」 원칙과는 이 세 곳이 예외가 된다.

## 2. ② 필터칩공용

**지금** — 상태 탭 칩(단일): 매입예정·클레임·업무일지결재·포털 / 다시 누르면 해제되는 칩: 사용자 관리(등급·역할) / KPI 카드 켜기·끄기: 관리자 / 체크박스 켜기·끄기: 알림톡 로그·포털 / select: 관리자 3·감사 로그 6·알림톡 로그 1·매입예정 등록자.
- 칩 CSS 는 공용 클래스가 없어 화면마다 Tailwind 문자열 복붙(users 는 `$chipOn/$chipOff` 변수).
- 건수 뱃지 계산이 제각각: 매입예정 = group by 1번 + 검색 반영 / 클레임 = group by, **검색 미반영** / 관리자 KPI·알림톡 = 필터 무관 전체 / 업무일지결재 = 전량 get 후 PHP.

**board 에 맞추면**
- 동작 종류는 **단일(해제 가능 여부 옵션)·켜기/끄기** 둘로 충분하다. 다중·3상태 순환은 board 에 쓰는 곳이 없다 → 만들지 않는다(필요해지면 추가).
- `<x-…filter-chips>` 하나로 칩 모양·건수 뱃지 자리를 통일. 탭 정의는 지금처럼 단일 출처(`PurchaseListing::TABS` 등)에서.
- select 필터(상태·출처·회신·변경자·항목)는 칩으로 바꾸지 않는다 — 선택지가 많다. ⑤ 콤보 대상(사람)만 따로 본다.
- 뱃지 규칙을 하나로: 「목록과 같은 조건(검색 포함)으로 센다」(매입예정 방식).

**Jin 결정 ②** 클레임 탭 건수를 검색 반영으로 바꿀지(작은 동작 변경). 업무일지결재 탭은 「내 차례」 판정이 PHP 라 공용 `counts` 에 화면이 직접 넣는 것으로 둔다.

## 3. ③ 헤더정렬공용

**지금** — 헤더를 눌러 정렬하는 곳은 현지확인 배정 요약표(inspection/index:123-166)와 포털 미수금(portal/index:278-285, 2047-2066) 둘뿐이고 둘 다 **받아 온 행을 메모리에서** 정렬한다. DB 목록(매입예정·관리자·감사 로그·사용자·클레임)은 전부 고정 정렬(`latest()` 등). ERP 의 `StackedHeaderSort` 에 해당하는 것이 board 엔 없다.

**board 에 맞추면** — 이 단계는 정리가 아니라 **새 기능**이다.
- 트레이트는 car-erp `app/Support/StackedHeaderSort.php` 를 옮겨 온다(복사 — 두 레포는 코드를 공유하지 않는다) + `<x-…sort-th>`.
- 후보: 매입예정(등록일·차량번호·최종금액·상태), 관리자(같음), 사용자 관리(이름·등급·역할 — 지금 등급순 고정), 클레임(접수일·상태·금액). 감사 로그는 시간순 고정이 맞다.
- 기본 정렬은 지금 것 유지(매입예정 = 최신순). 겹침 정렬(최대 5단)까지 필요한지는 화면이 작아 의문 — 1단 정렬만으로 시작해도 된다.

**Jin 결정 ③** 어느 화면·어느 칸에 정렬을 넣을지, 겹침 정렬까지 넣을지.

## 4. ④ 새 화면 틀 + 가드

- 정적 테스트 3개면 된다: (가) 목록 화면에 `wire:model.live…="search"` 류가 있으면 빨강(「치는 동안 조회 금지」) (나) 검색칸은 `<x-…search-bar>` 를 거친다 (다) 정렬 헤더의 key 가 전부 `sortableKeys()` 에 있다. board 엔 같은 식의 정적 가드 선례가 있다(`test_every_literal_lang_key_used_in_code_exists_in_both_locales`).
- 예외 목록에 포털(ERP 응답 화면)을 명시.
- stub 은 파일 복사로 충분(artisan 명령까지는 과하다 — board 새 목록 화면은 드물다).

## 5. ⑤ 드롭박스콤보공용

**지금** — 콤보 부품이 없다. 검색되는 입력은 `x-region-input`(지역, 4화면)과 `<datalist>`(은행·위치)뿐. 사람·거래처 고르기는 전부 평범한 `<select>`:
- 경매/구매 드로어 **바이어·컨사이니**(auction/index:1271, 1300) — ERP 바이어 명부라 수십~수백 개. **실사용 가치가 가장 크다.**
- 매입예정 등록자 필터(listings/index:1829), 감사 로그 변경자(audit/index:224), 현지확인 배정 사용자(inspection/index:381), 포털 선적 계획 컨사이니·포워딩사(portal/index:1975, 1983), 탁송 업체(transport/tab).

**board 에 맞추면** — car-erp `resources/views/components/erp/combobox.blade.php` 를 옮겨 온다(props 동일: model·options·selected·placeholder). 폰 다크 모드 글자색 명시(정본 §9-1) 포함.
- ⚠️ 경매/구매 바이어 select 는 🔒 잠금 바이어 표시·`updated` 훅(매입 등록 락 판정)이 붙어 있다 — 값·훅은 그대로, 겉모양만 교체. 씬 점검 2b(구매확정·재고매입·입금요청)가 이 칸을 `select` 로 조작하므로 **러너의 select 단계도 같이 고쳐야 한다.**
- 결재선 창의 직급별 select 는 후보가 1명이라 콤보로 바꾸지 않는다.

## 6. ⑥ 결재트리공용

**지금 — 두 벌**

| | 클레임 | 업무일지 |
|---|---|---|
| 단계 표 | `claim_steps`(revision·acted_by·note 있음) | `work_journal_steps`(skipped 상태 있음) |
| 결재선 정하는 때 | 담당자 [결재 요청] 창 | 상신 때 기본 → **팀장 승인 창에서 다시 지정**(11-16) |
| 후보 | `Claim::lineCandidates()` | **같은 함수 재사용** |
| 선택 검증 | `requestApproval` 안 인라인 | `pickLine()` — 주석 「클레임과 같은 규칙」, 코드는 복제 |
| 차례 판정 | `canDecide`(super 대행 가능) | `canApprove`(대행 없음) |
| 반려 | 그 건 **종결**(재요청 = 회차+1) | **기안 전체가 첫 결재자 결재 전으로** + 고른 사람만 반송(11-19) |
| 잠금 | `lockForUpdate` 있음 | 승인·반려에 **없음** |
| 알림 | 알림톡(서명 링크 5일) + 푸시 | 푸시만 |
| 결재선 창·단계 띠 | claims/index:618-640 · `_steps.blade.php` | approvals 안에 **같은 마크업 복제** |

**board 에 맞추면 — 권장: 「겹치는 조각만」 먼저**
1. `App\Support\ApprovalLine`(가칭) — 후보(`candidates()`)·선택 검증(`pick()`)·기본값을 한곳에. `Claim::lineCandidates`·`ClaimService` 인라인 검증·`WorkJournalService::pickLine` 이 이걸 부른다. **동작 무변경**(테스트 `ClaimsTest`·`WorkJournalTest` 가 가드).
2. `<x-…approval-line-picker>` — 결재선 창 한 벌(지금 두 화면에 복제).
3. `<x-…approval-steps>` — 결재 줄(단계 띠) 한 벌.
4. 업무일지 승인·반려에 `lockForUpdate`(더블클릭 방지 — ERP 정본 §9-2 도 「반려에도 잠금」을 적었다).
- **표 합치기(`approval_steps` 다형)는 이번에 하지 않는다** — 두 기능 다 운영 중이고(클레임은 서명 링크·회차, 업무일지는 기안 묶음·되돌리기) 반려 의미가 본질적으로 다르다. 합치면 마이그레이션 + 운영 데이터 이관이 생긴다. 조각을 묶고 나서 세 번째 결재 대상이 생길 때 다시 본다.

**ERP 정본과 다른 점(Jin 확인 필요)**
- ERP 정본 §9-2 = 「대표는 반드시 끝」(대표 필수). board = 「지정한 마지막 사람이 최종, 대표 없어도 됨」(클레임 11-11·업무일지 11-16 Jin 확정). **board 는 board 규칙을 유지**하는 것으로 본다 — ERP 와 같은 부품을 쓰지 않으니 충돌은 없지만, 용어 「결재트리공용」이 양쪽에서 다른 규칙을 뜻하게 된다.
- ERP 는 중간 승인 때 기안자 알림 없음(재제안 금지 표시). board 업무일지는 최종·반려 때만 작성자 알림 — 같다.

**Jin 결정 ⑥** (가) 조각만 묶기(권장) vs 표까지 합치기 (나) 업무일지에도 super 대행 승인을 둘지(클레임엔 있음) (다) 업무일지 결재 알림을 알림톡으로 올릴지(지금 푸시만 — BizM 템플릿 승인 필요).

## 7. ERP 목록엔 없지만 board 에서 같이 묶을 만한 것

- **페이지당 건수** — 선택지가 화면마다 다르다: 매입예정 [건수만·10·20·30·50·100], 사용자·알림톡 [10·30·50·100], 감사 로그 [25·50·100]/[15·50·100], 관리자·클레임 = 20 고정. 화이트리스트 검사 위치도 제각각. 트레이트 `ListPaging` 하나로 줄일 수 있다(선택지는 화면 선언).
- **`#[Url]` 기준** — 관리자·사용자(검색·칩)는 주소창에 안 남는다. 공용이 가져가면 저절로 통일된다(새로고침해도 필터 유지 = 작은 동작 변경, 이득).
